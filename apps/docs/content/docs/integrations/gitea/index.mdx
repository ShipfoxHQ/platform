## Authentication

Shipfox connects to a Gitea instance through a read-only service account. The
integration connection is scoped to one Gitea organization. An instance admin
provisions push delivery to Shipfox out of band, because the service account
cannot manage organization hooks.

Gitea is the local stand-in for GitHub in the evaluation stack. Deployed
installations (self-hosted or cloud) connect GitHub.

## Integration connection identity

The slug of a Gitea integration connection defaults to `gitea_<organization>`,
where `<organization>` is the connected Gitea organization. For example,
`gitea_shipfox`. Use the slug of the workspace integration connection as a
workflow trigger `source`.

```yaml
triggers:
  on_push:
    source: gitea_shipfox
    event: push
```

For trigger field rules, see the [workflow schema reference](/reference/workflow-schema#trigger-fields).
