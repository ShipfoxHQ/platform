This reference lists the Gitea push event that Shipfox delivers to a Gitea
integration connection. See the [Gitea overview](/integrations/gitea) for
authentication and setup.

## Payload

Shipfox passes the raw Gitea webhook body to a run as `event`. Gitea owns the
payload schema and can add fields. Treat `event` as untrusted data. See
[Templates carry untrusted data](/understand/data-and-templating#templates-carry-untrusted-data)
before using payload fields in workflow decisions or commands.

See the [Gitea webhook reference](https://docs.gitea.com/usage/repository/webhooks/)
for the push payload schema.

## Delivery behavior

Shipfox supports push webhooks. Signed non-push deliveries are recorded for
deduplication and acknowledged without starting a workflow. A push that deletes
a branch is acknowledged without publishing a `push` event.

## Trigger fragment

Replace `gitea_shipfox` with the slug of your Gitea integration connection:

```yaml
triggers:
  on_push:
    source: gitea_shipfox
    event: push
```

For trigger field rules, see the [workflow schema reference](/reference/workflow-schema#trigger-fields).
