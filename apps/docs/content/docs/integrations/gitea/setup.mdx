Connect Gitea when a repository push should start a Shipfox workflow. See the
[Gitea overview](/integrations/gitea) for its capabilities.

## Before you begin

You need access to workspace integration settings. You must also be able to
connect a Gitea organization.

To verify a run, you also need a project that can sync workflows and an online
runner with the `shipfox` label.

## Connect the Gitea organization

<Steps>
  <Step>

    **Start the integration connection**

    Open **Settings → Integrations** in the workspace. Select **Gitea**, then
    start the integration connection.
  </Step>
  <Step>

    **Enter the organization name**

    Enter the Gitea organization to connect. Shipfox checks that the
    organization exists and is not already linked to another workspace.
    It does not verify that the workspace user administers the organization.
  </Step>
  <Step>

    **Record the slug of the integration connection**

    Open the new integration connection's menu. Select **Use this integration**. Copy the
    slug from the trigger example. Workflows use that value as `source`.
  </Step>
</Steps>

An instance admin provisions a push-only webhook from the organization to
Shipfox. Configure its shared secret with the `GITEA_WEBHOOK_SECRET` value used
by the Shipfox deployment. Unsigned or incorrectly signed deliveries receive
HTTP 401.

Signed non-push deliveries are recorded for deduplication and acknowledged
without starting a workflow. Branch-deletion pushes are also acknowledged
without publishing a `push` event.

## Add a test workflow

Create `.shipfox/workflows/check-gitea-connection.yml`. Replace `gitea_shipfox`
with the slug of your Gitea integration connection. This is a complete workflow:

```yaml
# yaml-language-server: $schema=https://www.shipfox.io/docs/workflow.schema.json
name: Check the Gitea integration connection
runner: shipfox

triggers:
  on_push:
    source: gitea_shipfox # Replace with the slug of your Gitea integration connection.
    event: push

jobs:
  check:
    steps:
      - run: echo "Received a Gitea push!"
```

Commit and push the workflow to the project's default branch. Wait for **Check
the Gitea integration connection** to sync.

## Verify a triggered run

Make sure the integration connection is enabled in **Settings → Integrations**. Select
**View recent events**. Push one more safe commit to a connected repository.

Open the push event and its linked run. Confirm that the log prints the push
message. This proves the webhook delivered the push and the trigger used the
saved integration connection slug.

The [Gitea events reference](/integrations/gitea/events) lists the shipped event
names and payload behavior.
